# JD 对照缺口分析流程

把一段 JD 拆成可核验的能力点, 逐点对照用户简历与面试记录, 输出缺口清单。
**硬约束**: 每一条证据都必须能回溯到简历字段或面试记录原文, 不得臆测。

## 步骤

1. **取 JD 原文**: 若用户已建投递档案, 用 `read_application_jd(application_id)`
   读取当前版本正文; 若用户直接粘贴了 JD, 直接使用粘贴文本并说明来源为"用户粘贴"。
   - 降级: 若既无档案也未粘贴 JD, 请用户补上 JD 文本后再继续。

2. **拆核验点**: 把 JD 拆成一组原子能力点 (技能/经验/领域), 每个核验点是一句
   可判定"有/无/不足"的陈述。合并同义项, 不要逐词罗列。

3. **映射证据**:
   - 简历证据: `read_resume_summary()` 取结构化摘要 (技能/经历/项目)。
   - 面试证据: `list_interview_records()` 找相关记录逐题原文;
     `read_report_weak_points(report_id)` 取报告中的薄弱点。

4. **逐点判定**并输出清单, 三档:
   - **已覆盖**: 简历或记录中有明确证据 (附出处)。
   - **证据不足**: 有相关经历但深度/量化不够 (指出缺什么)。
   - **未提及**: 简历与记录中均无 (列为待补)。

5. **补强建议**: 对每个"证据不足/未提及"项, 写明"需要补什么证据 +
   在简历哪个位置补 + 如何准备一段可讲述的经历"。

## 输出

Markdown 表格或分组清单, 三列为「核验点 / 判定 / 证据或缺口」。
不输出录用概率、ATS 打分或任何评分。
