> 版本：v1.3（终版答辩稿） · 2026-10
> 形态：本地部署的 Web 应用（FastAPI 后端 + Vue 3 单页前端 + 离线语音模型）
> 主文档：本说明书；启动与开发说明见 `README.md`、`AGENT.md` 和 `docs/START_GUIDE.md`。

## 一、项目概述

### 1.1 一句话介绍

AI 模拟面试官系统是一个**本地部署**的智能面试训练平台：用户导入简历、选定岗位后，由基于 LangGraph 状态图的面试引擎进行多轮仿真面试（出题 → 追问 → 评分 → 报告）；报告数据跨场次聚合为**成长档案**，弱项沉淀进**个人知识库**（双链笔记 + 混合检索 + 知识图谱），并由一层**统筹智能体**通读全部数据、给出可确认执行的定向训练建议——形成"面试 → 复盘 → 学习 → 再面试"的完整闭环。

### 1.2 背景与需求来源

求职技术岗位的面试准备存在三重困境：

1. **练习环境缺位。** 同学互面缺专业度，真实面试机会成本高；直接问大模型又缺流程约束——不出题、不追问、不评分，练完留不下任何可复盘的数据。
2. **复盘不成体系。** 面完只有"感觉不好"的印象。弱点散落在各场对话里，没有人帮用户做跨场次聚合：上周弱在哪、这周是否有进步，全凭记忆。
3. **资料散落孤立。** 笔记、面经、报告、岗位 JD 各存一处，面试前想查"我笔记里怎么记 RAG 分块的"需要切换多个应用，知识与使用场景断裂。

### 1.3 设计目标

- 把"练一场面试"扩展成"练 → 测 → 复盘 → 定向学习 → 再练"的**可度量闭环**；
- 全部核心数据与模型**本地部署**（简历、面试记录、笔记不出本机，语音识别完全离线）；
- 系统输出的**每个数字可溯源**：不产出任何 ATS 分、匹配百分比、录用概率等伪指标。

## 二、需求分析

### 2.1 用户画像与核心场景

| 用户场景 | 对应能力 |
|---|---|
| 想练面试的学生：上传简历 → 选岗 → 开一场 8 题中级面试 | 面试引擎（standard / project / hybrid 三模式） |
| 面完想复盘：看雷达报告、看哪里弱 | 雷达报告页 + 成长档案页 + 弱项趋势 |
| 想针对性补弱：把弱项整理成学习任务 | learning_suggestions 一键入库 → 知识库笔记 |
| 面试前突击：查自己笔记里记过的知识点 | 知识库 RAG 问答 + 父文档检索 |
| 管理求职进度：投了哪些公司、走到哪一步 | 投递看板（七阶段 + 时间线 + 结果复盘） |
| 一句话让系统替自己安排："帮我复盘上周并给下周计划" | 统筹智能体 + 周复盘技能 |

### 2.2 功能需求（已实现）

1. **用户体系**：JWT 登录/注册，报告、简历、笔记、投递档案、助手会话全部按用户隔离。
2. **简历处理**：PDF 解析或粘贴文本；原文与结构化字段落库、可编辑、带证据核验；人工审核确认后才能参与 JD 分析与面试。
3. **JD 分析**：证据化输出（硬性要求 / 已满足 / 未满足 / 证据不足 / 追问建议），schema 层面禁止评分、概率、ATS 分与录用结论。
4. **JD 版本管理**：正文与来源不可变版本（记录时间、SHA-256、恢复来源）；恢复 = 追加新版本；并发更新返回 409 并保留本地草稿。
5. **投递看板**：七阶段跟踪（待投递/已投递/筛选/面试中/Offer/已拒绝/已撤回）、时间线备注、结果复盘、面试报告回挂。
6. **模拟面试**：题量 1–20、难度三级自适应、三种模式；低分追问（仅 3≤分<7 触发）；自一致性采样评分（N=3 取中位数）；提示封顶规则；浏览器 TTS 朗读与本地语音输入。
7. **报告与成长**：单场雷达报告（四维分 + 分类均分 + 逐题得分点）；跨场成长档案（走势/雷达叠加/分类掌握度/难度分布）。
8. **个人知识库**：双链笔记、Markdown 编辑、AI 解读、语义边知识图谱（相似度阈值 + kNN 截断）、父文档检索、RAG 问答、报告建议一键入库与覆盖度检查。
9. **统筹智能体**：36 个注册工具；只读工具自动执行，写操作提案-确认；跨会话长期记忆（三门槛写入 + 半衰期检索 + 冲突取代）；上下文摘要压缩；可扩展技能运行时。
10. **跨图协作（handoff）**：助手批准面试提案 → 定向开考；报告生成 → 事件回流 → 助手主动简报。
11. **语音**：SenseVoice int8 ONNX 离线识别 + Silero VAD 防幻听 + 噪声校准；转写保留 3 秒复核不自动发送。
12. **一键演示**：`start-demo.ps1` 检查环境与端口 → 启动后端 → 健康检查 → 启动前端 → 打开浏览器。

### 2.3 非功能需求

| 类别 | 要求 | 现状 |
|---|---|---|
| 隐私 | 简历/面试/笔记数据不出本机 | 全部本地 SQLite + 本地模型；ASR 完全离线 |
| 可靠性 | 会话刷新/后端重启可恢复 | LangGraph SQLite checkpointer + 消息双轨持久化 |
| 可测试性 | 行为可回归 | 251 项后端单测 + 25 条真实 LLM 评测 + WS 端到端 36 项检查 |
| 安全 | agent 不越权、不泄露 | 身份服务端注入、三闸门权限、提案必须确认、防提示注入数据标签 |
| 性能 | 出题流式首字、评分延迟可控 | 逐字 astream 推流；只读工具并行执行；fast/strong 模型分层 |

### 2.4 明确不做（范围控制）

不自动向雇主投递或联系招聘方；不做企业招聘系统对接；不做在线职位抓取；不做多后端进程协调（当前单进程互斥锁）。

## 三、总体设计

### 3.1 三层智能体架构

自主性的分配遵循一条判据：**能 workflow 就别 agent，能单 agent 就别多 agent。**

```
┌────────────────────────────────────────────────────────────┐
│ L3 技能层   技能运行时（SKILL.md 目录 + 三级渐进披露）          │
│             知识库内核（父文档检索 / 双链 / 图谱——只被调用）     │
├────────────────────────────────────────────────────────────┤
│ L2 统筹层   统筹智能体：手写五节点 LangGraph 图                 │
│             36 工具 · 三闸门权限 · 提案-确认 · 长期记忆 · 压缩   │
├────────────────────────────────────────────────────────────┤
│ L1 引擎层   面试引擎：14 节点 StateGraph + 3 个 interrupt       │
│             数据底座：SQLite×5 + Chroma×3 + BM25/BGE           │
└────────────────────────────────────────────────────────────┘
```

- **面试引擎（workflow）**：面试有硬性阶段与终止条件，必须可预测、可评测——LLM 只负责内容生成，不负责流程控制。
- **统筹智能体（agent）**：跨报告分析需要模型自主决定读几份报告、调哪些工具——自主性放在这一层。
- **技能运行时（程序性知识）**：可复用的标准流程（如周复盘五步）以目录形式沉淀，加技能不加代码。

两层 LangGraph 图（面试图 `iv_` 前缀 / 助手图 `as_` 前缀）**永不互相调用**，只通过"提案 + 前端交接 + handoff 事件表"通信。

### 3.2 技术选型与理由

| 维度 | 选型 | 理由 |
|---|---|---|
| 流程编排 | LangGraph 1.2.10（手写图） | `interrupt()` 人在回路 + AsyncSqliteSaver 断点续跑；不使用已废弃的 `create_react_agent`，官方 HITL 中间件 resume 契约脆弱 |
| 模型 | DeepSeek 兼容接口，fast/strong 分层 | 出题/闲聊走 fast 控成本，评分/报告走 strong 保质量 |
| 检索 | BM25(jieba) + BGE-base-zh-v1.5 + RRF(k=60) | 题库专有名词的精确匹配靠 BM25，语义泛化靠向量，RRF 免调参融合 |
| 知识库索引 | Chroma（cosine）+ 父文档检索 | 子块索引父块返回，避免断章取义 |
| 后端 | FastAPI + 双 WebSocket | 面试流与助手流互不干扰 |
| 前端 | Vue 3 + Vite，手写 SVG 图表 | 无重型图表依赖，生产构建约 5 秒 |
| 语音 | SenseVoice int8 ONNX + Silero VAD | 完全离线、零 token 成本；VAD 防静音幻听 |
| 存储 | SQLite×5（用户/知识/简历/投递/助手）+ checkpoints.db | 单机零运维；参数化查询按用户隔离 |

### 3.3 数据流（面试主链路）

```
登录 → 上传/粘贴简历 → 解析与结构化 → 人工审核
  → 选岗（题库岗位或投递档案关联 JD）→ 配置（题量/难度/模式/JD 注入）
  → WS /ws/chat：configure → opening → prepare/emit → wait_answer(interrupt)
      → score_initial → (低分? prepare/emit followup → wait_followup(interrupt))
      → score_combined → finalize → …循环… → closing → wait_report(interrupt) → summary
  → 报告 JSON+MD 落盘 → 报告页 / 成长档案聚合 / 可回挂投递档案
  → learning_suggestions 一键入知识库 → 复盘笔记
```

## 四、核心模块设计

### 4.1 面试引擎：LangGraph 状态机

- **14 节点 / 3 个 interrupt**：configure、opening、prepare_question、emit_question、wait_answer、score_initial、prepare_followup、emit_followup、wait_followup、score_combined、finalize_question、closing、wait_report、summary。
- **重放纪律（工程约束一）**：`interrupt()` 恢复时 LangGraph 从包含它的节点开头**重跑**。因此所有等待节点在 interrupt 之前零副作用（无随机选题、无 LLM 调用、无写盘），"准备+流式输出"与"等待输入"强制拆分为两个节点。
- **评分**：自一致性采样 N=3 各维取中位数；得分点按"过半采样命中"归类；提示 1 次封顶 8 分、2 次封顶 6 分并四维等比缩放。
- **追问策略**：仅 3≤初始分<7 触发；方向优先题库预置 followup_directions，回退评分 missed_points。
- **难度自适应**：≥7 分 streak+1 连续两次升级；<4 立即降级；全程记入 difficulty_changes。
- **数据契约防泄漏**：跨题出题衔接只读候选人回答原文与表现档位，**不读评分依据**（防止出题链复述评分造成"候选人提到过"的幻觉）；低分回答另注入禁令。

### 4.2 混合检索与知识库

- **题库检索**：jieba 分词 → BM25 与 BGE 向量双路召回 → RRF(k=60, 权重 0.4/0.6) 融合 → 截断。
- **父文档检索**：短文整篇入库；长文"子块索引 + 父块返回"；切分按"行 → 标点句 → 字符硬切"边界优先级。
- **知识图谱**：显式双链之外自动添加语义边（相似度 ≥0.66，kNN top-3 截断防毛球化），cytoscape 力导布局。
- **报告→知识库**：learning_suggestions 一键入库生成笔记，并做覆盖度检查（已覆盖 / 覆盖不足）。

### 4.3 统筹智能体

- **手写五节点图**：load_context → agent → tools → wait_confirm (+ apply_rejection)。理由：实装 LangGraph 1.2.10 中 `create_react_agent` 已废弃；官方 HITL 中间件决策条数契约脆弱；手写图与面试图同构，降低心智成本。
- **配对不变量**：任何路径下每个 tool_call 必有配对 tool_result（异常/被拒/非法工具名均合成错误消息），逐路径测试断言。
- **36 个工具**：只读（报告/雷达/弱项/记录检索/笔记/KB/简历/JD/题库元数据）、写入（记忆/投递档案/JD 更新与恢复）、提案（起面试/知识库会话/操作审批）、技能（列表/激活/卸载/读资源/执行脚本）。
- **权限三闸门**：硬拒绝 → 规则判定（risk×参数指纹 → allow/ask/deny，默认 ask）→ 用户审批；批准按 (工具, 参数指纹) 记忆，换参数重新审批；拒绝理由回灌模型。
- **提案-确认契约**：提案工具对模型不可见（起面试等高代价动作由代码发起）；可编辑字段服务端白名单；原提案/编辑后/提交事实三份摘要独立；编辑后旧提案作废（StalePendingAction）。
- **长期记忆**：importance<6 拒写、不可信来源拒写、冲突就地 supersede；检索分 = 相似度 × 关键词 × 0.5^(天数/30) × 重要度；recall-loop 防护（注入过的内容禁止再写成记忆）；记忆面板可见可删。
- **上下文压缩**：四步按代价升序（大结果落盘留指针 → 切点避开配对 → 缩旧工具结果 → LLM 摘要）+ rapid-refill 熔断；动态段置于静态前缀之后保前缀缓存。

### 4.4 技能运行时（遵循 Agent Skills 开放标准）

- **形态**：`backend/skills/<name>/SKILL.md`（frontmatter: name/description/allowed-tools/metadata），加技能 = 加目录，零代码改动。
- **三级渐进披露**：L1 元数据常驻（约 50 token/技能，上限 20）→ L2 激活后正文注入（同时最多 2 个，6 轮未引用自动卸载）→ L3 references 按需读、scripts 经审批执行。
- **路由**：description 是唯一路由文本，模型自主调用 `activate_skill`；服务端只做规则校验。
- **安全**：allowed-tools 引用不存在的工具则整技能不加载；激活后调用未声明工具软门控提示；脚本执行四重限制（execute 闸门 + 必人工确认 + 路径前缀校验 + 30s 超时/截断）；技能正文以数据标签包裹并声明不得覆盖安全策略；单技能失败隔离。
- **内置技能**：`weekly-interview-review`（拉趋势→定弱项→读原文→3 条计划→沉淀记忆）；`jd-gap-analysis`（JD 拆核验点→映射简历证据→覆盖/缺口清单）。
- **评测发挥作用的实证**：技能路由评测 route-022 曾暴露"模型绕过技能、直接零散拼工具"的缺陷——通过强化 L1 路由指令与技能 description 修复，修复后全量评测该用例以完整的"激活→五步流程→卸载"轨迹通过，且负样本（不应触发）无误触发。

### 4.5 跨图协作 handoff

出站：批准面试提案 → 登记 30 分钟 TTL 意图（单次消费）→ `/ws/chat` 收到 config 时按用户消费并注入定向主题。
回流：报告生成 → 写完成事件（均分/岗位）→ 助手每轮 drain 未 ack 事件并主动简报（drain 即 ack，同一结果只简报一次）。
钩子极薄：handoff 读写异常全部降级，不阻断面试与助手主流程。

### 4.6 成长档案（v1.3 新增）

- 后端 `GET /api/reports/growth`：`backend/growth.py` 纯确定性聚合——逐场均分时间线、四维分、题目级分类聚合（均分/低分率/delta，弱项置顶）、难度分布、总览指标（近期趋势 = 最近 3 场均分 − 之前 3 场均分，不足 4 场为 null）。
- 前端 `/growth`：总览四卡、SVG 均分走势（渐变面积 + 悬停详情）、四维雷达叠加（最新一场 vs 个人均值）、分类掌握度条（按分值配色）、难度分布、最近 12 场明细一键跳报告。
- 零 LLM：所有数字可在报告原文复核；5 项专项单测覆盖聚合口径、用户隔离、空态与无效文件。

### 4.7 语音交互

本地 SenseVoice int8 ONNX 推理（不联网不耗 token，CPU 解码走线程池）；Silero VAD 流式喂音频（噪声校准、最低语音时长、静音停止、低能量拒绝）；转写只填输入框保留 3 秒复核；朗读用浏览器原生 SpeechSynthesis（暂停/继续/跳过）。模型经 `python main.py fetch-models` 按固定清单下载，逐文件校验大小与 SHA-256，支持断点续传。

## 五、关键技术与创新点

1. **三层智能体的自主性分配。** 面试流程 workflow 化（可预测、可评测），跨报告分析 agent 化（有自主），流程知识技能化（可扩展、可评测）——每层有明确判据，而非堆砌 agent。
2. **提案-确认权限模型。** 把"人在回路"从弹窗升级为契约：提案对模型不可见、可编辑字段白名单、三份摘要独立、陈旧提案作废、并发更新不覆盖——全部有测试锁定。
3. **遵循开放标准的技能运行时。** 三级渐进披露控制 token 成本；description 唯一路由；allowed-tools 预授权与软门控；误触发率单列指标作为扩编停止判据。
4. **证据链优先的评估观。** 系统性拒绝伪指标（无 ATS 分/匹配百分比/录用概率）；JD 分析三态证据化；成长档案零 LLM 确定性聚合；评测中安全类用例按人工判据标 pending_review 不伪装通过。
5. **工程纪律的制度化。** interrupt 等待节点零副作用、配对不变量逐路径断言、断言核实台账（任何机制断言须有源码出处或验证脚本）——三条纪律都写成测试而非口头约定。

## 六、测试与质量保障

| 层级 | 内容 | 规模 |
